# Phase 3 profile extraction and storage

After final `DocumentFindingsV1` storage, scans with a Phase 2 schema hash queue a separate profile pass. Existing scans without a hash retain their findings and do not get fabricated profiles. Each PDF page group or image request sends the complete historical schema, validated record plan, original observations with final evidence IDs, and private source bytes through the existing stateless Gemini Interactions request. Profile responses use contract version `1.0`; original V1 findings and its batch cache are not changed.

`ProfileProjection` checks the schema hash, record ownership, entity role, field path and type, row reference, source page and evidence IDs. Bad values become warnings. A malformed record is rejected without rejecting valid sibling records. Cross-batch values for the same path and row remain separate with a review warning. Unassigned observations remain in V1, and profile-pass unresolved items are saved on the scan. A profile is stored only after all of its page groups validate; retries preserve its original projection and reuse validated private profile-batch responses. No customer foreign key or customer write is involved.

The development migration adds scan profile status/error/unresolved columns, `extracted_profiles`, and the Phase 4 review-event table. The document detail page shows extraction status, record count and a retry control; field review waits for Phase 4. Profile errors do not change V1 findings status.

The full canonical schema remains 60,072 UTF-8 bytes. A request containing it plus source and evidence is checked against a 20 MB inline JSON body limit before sending; fields are never dropped to fit. Fake-HTTP tests cover unlinked storage, related person and choice values, strict false/zero handling, nine independent profiles, cache reuse, and sibling recovery after a failed batch. Page groups run serially in one job with a 3600-second timeout; very long documents need separate profile-batch jobs before that limit is reached. The database queue default visibility is 3660 seconds, but target deployment worker timeout and queue visibility still need verification. Live Gemini accuracy remains unmeasured; no paid call was made.
