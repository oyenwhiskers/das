# Phase 4 profile review and correction

The document detail page links each stored Extracted Profile to a review page. The page groups proposed values by the historical schema's modules, lists unprovided fields, shows original and current values, evidence page references, profile warnings, unresolved scan observations, review status, and correction history. Routine value tables mask identification, tax, and account numbers. The original findings and original profile projection remain unchanged.

Active staff can correct or exclude a proposed value, add a missing value with source evidence, dismiss a warning with a reason, or move all values belonging to one entity to another profile in the same scan. A value moved outside the target's source pages is removed from the mergeable projection and retained in scan-level unresolved data. Corrections and append-only events commit in the same transaction. Both sides of an ownership move have revision checks and events. A stale revision fails visibly. A profile can be marked reviewed only after uncertain values, duplicate field/row keys, and profile warnings are resolved. Unassigned scan observations remain outside profiles and are displayed for staff inspection.

No customer data is written. No new migration was needed because Phase 3 created the review columns and event table. Focused and complete PHP tests pass, Pint passes, and Blade compilation and the review route were checked. Paid Gemini calls were not made. Phase 5 must implement matching and merge separately; the review status alone does not authorize a customer write.
